建任务时就选好电工

主管建任务时选定电工和调试时段 → 安全主管审核 → 经理批准 → 电工接单。经理不再派人。

船舱里没网，手机离线作业

电工接单时把开锁授权下载到手机；船舱里离线开锁、通电、上锁，记录先存手机，上甲板联网后补传。

超时有提醒，延时要审批

结束前 30 分钟提醒；延时经安全审核和经理批准；超时后继续合闸，必须扫主管出示的延时码。

超时与延时
结束前 30 分钟提醒四个角色。主管可申请延时，再经安全审核和经理批准；锁已打开，不再开锁。超时又没批延时：不能新开锁、合闸，断电收尾照常。超时后要继续合闸，主管出示延时码，电工手机扫码核验后才能合闸；主管没拿到码，要有人上甲板联网取码。
一次申请，解锁＋通电
这两件事在同一次现场作业中连续完成，但要分别记录结果。开锁成功不等于已经通电；其他锁定或作业冲突未解除，不能合闸。App 不直接控制断路器。
02 / 人员分工

每个人能做什么，不能做什么

“可以”表示由这类人员负责，但仍要核对任务、设备、指定人员、调试时段和授权。“—”表示没有这项操作权限。审批人不在时，由 AB 角代审代批。

调试主管

建任务（选锁、指定电工、选时段）→ 提申请 → 组织调试 → 快到时间时申请延时、出示延时码 → 当面或对讲机通知断电 → 查看收尾。

安全主管

审核任务和延时 → 通过或退回并说明原因。建议：补传后发现的违规、超时也通知安全主管。

调试经理

批准任务和调试时段，批准延时，或退回说明原因。不再派人。项目授权时可兼做项目管理。

电气操作员

接单并下载授权 → 船舱里离线核对、开锁、通电并拍照 → 超时后扫码才能继续合闸 → 分闸、验电、上锁并记录 → 上甲板自动补传。

项目经理

只管理、不审批：生成各角色注册码，确认扫码注册的人员，配 AB 角，移除退场人员。

开工前，人员怎么进来
项目经理（或授权的调试经理）生成本项目各角色的注册码；人员用自己的手机扫码，填写手机号、姓名、单位（电工另填特种作业操作证），自己设密码；所有角色都要项目管理员确认才生效。一人一个固定角色，可以参加多个项目，角色不能随意切换。
03 / 怎么看设备当前的情况

锁打开，不代表已经带电

要分别看：调试做到哪一步、有没有合闸或分闸、锁有没有锁好。船舱里发生的事，要等电工上甲板补传后，看板上才看得到。

解锁后待合闸

锁打开后，如果还没合闸，不能显示“已经带电”。

已记录合闸带电调试

显示调试时段和剩余时间；结束前 30 分钟提醒，超时又没批延时就不能再合闸。看板标明最后同步时间。

已通知断电仍待分闸

主管通知了断电，不代表已经断电。分闸记录补传上来之前，看板仍按带电显示。

已记录分闸待确认 / 上锁

还需要完成验电、隔离确认和上锁，整个流程才算结束。照片不能代替验电。

手动上锁后补齐记录，完成本次流程

现场检查和记录都要齐全。如果是操作员确认锁好，就写清楚，不能说成系统自动检测到锁好。

04 / 出问题时怎么办

出了问题，谁来处理

处理分工还需业务确认

超时、违规需要上报并跟进。建议：发现问题 → 关联任务 → 通知安全主管等相关人 → 处理并补记录 → 复核结束。具体由谁处理、谁复核，还需要确定。

安全审核或经理审批没通过，退给调试主管修改；修改后重新提交。把问题标为“已处理”，不代表设备已经断电或上锁。

06 / 落地情况

App 已经做到哪里，下一步改什么

本机演示版 alpha.7 已经能跑通：建任务指定电工和调试时段 → 安全审核 → 经理批准 → 电工接单 → 现场记录 → 结束前 30 分钟提醒 → 延时两级审批 → 超时不能开锁和合闸。NFC 实锁还没接入。

下一步按数据架构 v0.3 改成船舱里离线作业：接单时下载授权、记录先存手机再补传、延时扫码、分闸不依赖断电指令；另一条线做扫码注册、项目经理、AB 角和多项目显示。

开始开发，不等于已满足现场上线条件。
手动上锁的验收标准、异常处理分工、跨天和多锁冲突仍需细化。样锁已验证实际 NFC 开锁，但还不能自动判断手动锁是否锁好。
