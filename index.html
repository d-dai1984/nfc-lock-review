一次申请，批准后解锁并通电

主管申请 → 安全主管审核 → 经理批准并派人。不再另走一轮送电审批。

主管负责调试，电气操作员负责送断电

只有获派且获授权的电气操作员能用 NFC 开对应的锁；经理批准主管填写的调试时间。

现场手动上锁，再在 App 记录

主管申请结束后，电气操作员断电、检查、手动上锁，补齐记录后结束本次流程。

02 / 人员分工

每个人能做什么，不能做什么

“可以”表示由这类人员负责，但仍要核对任务、设备、人员资格和本次审批。“—”表示这类人员没有这项操作权限。

动作调试主管安全主管调试经理电气操作员

调试主管

建任务、填允许时间 → 提申请 → 看进度 → 组织调试 → 申请断电 → 查看收尾。

安全主管

收到待审任务 → 核对安全条件 → 通过或退回并说明原因。

调试经理

批准任务和时间 → 安排电气操作员 → 查看接单情况 → 换班或无人响应时加人、下发任务。

电气操作员

接任务 → 核对并用 NFC 开锁 → 现场通电、拍照 → 收到断电请求 → 断电、检查、手动上锁并记录。

本版不再单列“调试员”流程角色，调试工作由调试主管负责组织。管理员维护人员、设备、柜门、锁和权限，不因此获得审批或开锁权限。新增任务人员不等于新建账号或自动授予电气资格。

03 / 怎么看设备当前的情况

锁打开，不代表已经带电

要分别看：调试做到哪一步、有没有合闸或分闸、锁有没有锁好。App 能操作 NFC 锁，但不能替人操作断路器。

解锁后待合闸

锁打开后，如果还没合闸，不能显示“已经带电”。

已记录合闸带电调试

显示谁在调试、已经过了多久。允许时间由主管填写、经理批准；计时起止与提醒规则待定。

结束已申请仍待分闸

调试主管点了结束申请，不代表已经断电。分闸前仍要显示带电。

已记录分闸待确认 / 上锁

还需要完成现场检查和上锁，整个流程才算结束。照片不能代替验电。

手动上锁后补齐记录，完成本次流程

现场检查和记录都要齐全。如果是操作员确认锁好，就写清楚，不能说成系统自动检测到锁好。

04 / 出问题时怎么办

出了问题，谁来处理

以下处理办法还需业务确认

超时、违规需要上报并跟进。建议：发现问题 → 上传并关联任务 → 通知处理人 → 处理并补记录 → 复核结束。具体由谁处理、谁复核，还需要确定。

安全审核或经理审批没通过，退给调试主管修改；修改后重新提交。把问题标为“已处理”，不代表设备已经断电或上锁。

06 / 下一步落地

可以开始做 App 的主流程

先让四类人员把一条任务从申请走到收尾：建任务 → 审核审批 → 派单接单 → 解锁、通电记录 → 调试 → 断电、上锁记录。

同时做服务器权限检查、操作记录、任务进度同步和异常上报。界面切换角色不能代替真实权限；船内局域网可用是当前设计假设。

开始开发，不等于已满足现场上线条件。
计时与延期、换班后旧权限、异常处理分工、多人多锁冲突仍需细化。样锁已验证实际 NFC 开锁，但还不能自动判断手动锁是否锁好；“操作员确认上锁”方案需业务验收。

本页只更新流程，不代表这些功能已开发。旧版讨论意见仍保留在浏览器中，打开旧版查看或导出；新版问题不套用旧答案。
